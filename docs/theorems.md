# Shared theorem environments

Declare shared theorem environments in
[`common/styles/theorems.yml`](../common/styles/theorems.yml). The manifest owns
titles, styles, counters, reference names, and layout policies. Commit it with
`common/styles/generated-theorems.sty`. The hand-maintained `theorems.sty` loads
its dependencies, implements conditional list handling, and loads that package.

## Manifest format

The manifest has `schema_version: 1`, `defaults`, `list_environments`, and an
ordered `environments` mapping. For example:

```yaml
schema_version: 1

defaults:
  space_after: bigskip
  break_before_initial_list: true

list_environments: [enumerate, itemize, description]

environments:
  theorem:
    kind: theorem
    title: Theorem
    style: plain
    counter: {within: section}
    cref: {singular: theorem, plural: theorems}
  lemma:
    kind: theorem
    title: Lemma
    style: plain
    counter: {shared: theorem}
  remark:
    kind: theorem
    title: Remark
    style: remark
    counter: null
  proof:
    kind: provided
    provider: amsthm
```

Names use lowercase ASCII letters and digits, begin with a letter, and may end
with `*`. Reserved LaTeX environment names cannot be redeclared. A theorem
requires a nonempty single-line TeX `title`, a `style` (`plain`, `definition`,
or `remark`), and a `counter`. Use `null` for an unnumbered theorem,
`{within: section}` or `{within: chapter}` for an independent counter, or
`{shared: theorem}` to share an earlier numbered theorem's counter. Forward,
missing, and unnumbered counter references are errors; declaration order makes
counter cycles impossible.

Optional `cref` declares singular and plural reference names. The generator
uppercases their first character for `\Crefname`; names beginning with a TeX
command retain that command. Omit `cref` to retain cleveref's default behavior.
Titles and reference names must have balanced braces, valid parameter syntax,
and no comments or line breaks. Single-quoted YAML preserves TeX backslashes.

The only supported provided environment is `proof` from `amsthm`. Its entry
registers layout policies while retaining the package's proof title and QED
implementation. Removing an entry stops managing it; a provided environment
continues to exist in its supplying package.

## Layout policies

Each environment inherits `defaults` and may override either policy:

- `space_after: bigskip` appends `\par\bigskip` after the environment.
  `space_after: none` adds no extra spacing; native theorem spacing still applies.
- `break_before_initial_list: true` puts a leading block list below the heading.
  Set it to `false` to retain the native same-line layout for that environment.

The policies are independent. `list_environments` uniquely selects any of
`enumerate`, `itemize`, and `description`; an empty list disables list hooks.
Before a selected list starts, the runtime checks its immediate parent and
whether the theorem or proof heading is still pending. It flushes only that
heading with `\leavevmode\par` and keeps it with the first item across page
breaks. The no-break state is scoped inside the list. Ordinary prose, lists
following prose, nested lists, and lists outside managed environments retain
their existing behavior.
Lists inside intervening wrapper environments are outside this direct-parent
policy. Keep a theorem's `\label` immediately after its opening declaration.

## Generation and validation

```sh
ashaiy theorems generate
ashaiy theorems check
```

Generation validates the whole manifest before writing and reuses the repository's
guarded file updates. Check mode reports stale or missing output without writing.
Shared theorems also participate in `ashaiy generated generate/check`, including
when `--book` selects one book, and `ashaiy check source`.

The [schema](../config/schemas/theorems.schema.json) supplies editor completion
and structural checks; the Python loader checks counter references and TeX values.
Documentation checks compare the public environment list with this manifest.
TeX formatting derives numbered label placement from the same declarations,
rejects stale generated packages, preserves generated bytes, and invalidates its
cache when the manifest changes. Lean proof coverage retains its separate
mathematical policy.

After adding or removing an environment, update the public list and usage in the
[writing guide](writing-guide.md#theorem-environments), regenerate, and run the
[shared-style validation](CONTRIBUTING.md#validation-by-change-category).
